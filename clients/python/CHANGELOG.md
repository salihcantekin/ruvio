# Changelog

Notable changes to the Python client `ruvio-client` on PyPI. New entries go under "Unreleased"; `scripts/release_version.py` moves them under the version number when the package is released.

## Unreleased

- `renew(key, token, ttl_ms)` sends the server's `RENEW`: it extends a `LEASE` or `SEMAPHORE` holder by its token without releasing it (1 when the token is a live holder, 0 otherwise). Lease and permit handles gain `renew(ttl_ms)`. Needs a server that has `RENEW`.
- `ruvio.is_transient(e)` and `ruvio.may_have_run(e)` sort an exception for a retry policy of your own (tenacity, a loop): transient means trying again later can succeed (`ConnectionError`, `TimeoutError`, or the replies `LOADING`, `MASTERDOWN`, `CLUSTERDOWN`, `TRYAGAIN`, `READONLY`, `NOREPLICAS`); may have run is false only for a server error reply other than `NOREPLICAS`. The same rules as the other clients. Nothing changes on the command path.
- `idem_abort(key, fingerprint, owner)` (sync and asyncio) sends `IDEM key ABORT fingerprint owner`: it removes a pending record of that owner and fingerprint so the next `idem_begin` acquires the key at once, and returns `True`/`False` (`False` for a missing key, a completed record or another owner). `idempotent(...)` takes `abort_on_error=False`; with `True`, a raising `fn` sends `ABORT` and the original exception propagates (a failed abort is ignored). The default behavior is unchanged. Needs a server that has `IDEM ... ABORT`.
- TLS: `tls=True` (or a ready `ssl.SSLContext`) on `Ruvio` and `ruvio.asyncio.Ruvio` wraps every socket in TLS, verifying the certificate chain and host name against the system roots. `tls_ca_file` trusts a private CA, `tls_cert_file` and `tls_key_file` give mutual TLS, `tls_server_name` covers a certificate named differently from the host, and `tls_insecure_skip_verify` (off) skips the check. `ruvios://` and `rediss://` URLs turn TLS on. The handshake runs inside the connect. Default off: plain TCP, nothing changes.
- The asyncio client now has a command timeout like the sync client: `socket_timeout` (default 30 s, `None` for no limit) on `ruvio.asyncio.Ruvio` and `ClusterRuvio`. If no reply starts within it, every command waiting on the connection fails with `ruvio.TimeoutError`, the connection is closed, and the next command opens it again. A blocking command (`blpop`, `xread` with `block`, `wait`, ...) gets its own wait on top, and a wait of `0` has no deadline. Before, a half-open socket hung the caller unless it used `asyncio.wait_for`. Pass `socket_timeout=None` to keep the old behavior. Not measured on a real network; on loopback, 30,000 concurrent `get` calls ran at the same speed with and without it.
- The reply parser refuses a bulk string over 64 MiB and an array, set, push or map over 1,048,576 elements as a protocol error before it allocates, the same limits as the Rust and C# clients. Before, Python had no limit.
- `eval_cached(script, keys, args)` on the sync and asyncio clients runs a script by its SHA1 and sends the whole script only when the shard answers `NOSCRIPT` (`EVALSHA`, then `EVAL` once). The SHA1 is computed in the client; nothing changes for `eval` and `evalsha`.
- A cluster client now retries `-TRYAGAIN` up to 7 times, after waits doubling from 5 ms to 320 ms (635 ms in all), instead of 3 times after 5, 10 and 20 ms. A slot range moving between the nodes of a cluster is frozen for a few hundred milliseconds (about 170-240 ms in a local test), so the caller saw `TRYAGAIN` on every such move before. Only `TRYAGAIN` replies wait; other replies are unchanged.
- Fixed: following a failover after a `READONLY` reply skipped the node that refused in every round of the search, so a replica promoted a moment later (the usual case after the primary dies: the reconnect lands on the replica during the election) was used only once all rounds had run out, about 7 s with the default backoff. The refusing node is now skipped only while it still says `master` (a replaced primary does); once it answers `ROLE` as a replica, a later round takes it when it says `master`. Nothing changes while the connection is healthy.
- `follow_primary=` (default `True`) and `sentinel_master=` on the sync and asyncio clients: a standalone client with two or more `seeds`, or a coordinator name, finds the primary again after a failover. A reconnect asks the seeds which node answers `ROLE` with `master` (following the primary a replica reports) and connects to it, falling back to the seed order; a `READONLY` reply starts a search for the primary (up to 8 rounds, 100 ms doubling to 2 s apart), moves the connection and sends the refused command once more, except inside a `multi()` transaction and for pipeline commands. With `sentinel_master` the seeds are coordinators asked with `SENTINEL get-master-addr-by-name` (the first connect raises `ProtocolError` when none names a primary). A healthy connection sends nothing extra; `follow_primary=False` restores the old behavior, and a client with one seed and no coordinator name is unchanged. Closing an asyncio client while a search for the primary runs ends the search and fails the held commands with `ConnectionError` (the search no longer opens the connection again after the close). When several pipelined asyncio commands are refused with `READONLY`, the replies still unread on the old connection are read and retried before it is closed, instead of failing with `ConnectionError`.
- `client_durability(replicas, timeout=None)` sends `CLIENT DURABILITY REPLICAS n [TIMEOUT ms]`, and the `durability_replicas=` / `durability_timeout_ms=` options send it on every connection the sync, asyncio and cluster clients open, so replies wait until that many replicas have the writes on disk.
- The sync and asyncio cluster clients follow `-ASK slot host:port` (they send `ASKING` and the command to the named node in one write, and leave the slot map alone) and retry a command answered `-TRYAGAIN` (see the entry above for the schedule). `ASK` and `MOVED` share one budget of 3 redirects per command. `TRYAGAIN` stays a plain `ResponseError`; it is only looked for on error replies. A pipeline gets it as that command's error.
- **Behavior change:** `StreamEntry.fields` is now a list of `(field, value)` tuples in stored order instead of a `dict`, so a field name written twice (`XADD s * f 1 f 2`) is no longer collapsed to its last value; use `dict(entry.fields)` for the old shape. Applies to `xrange`, `xrevrange`, `xread`, `xreadgroup`, `xclaim`, `xautoclaim` and `xinfo_stream`. Fixed: `hrandfield(key, -n, withvalues=True)` returned each field once; it now returns all `n` pairs, repeats included.
- **Behavior change:** `socket_timeout` of the sync client is now 30.0 seconds by default (was `None`, no limit); `None` turns it off. A blocking command gets its own wait on top (`BLPOP k 5` may take 5 s plus the timeout; a wait of 0, or one the client cannot parse, has no deadline; a pipeline takes its largest wait), and a Pub/Sub or `MONITOR` connection never times out while it waits for messages (issue #48 follow-up).
- `move_slots(first, last, shard)` and `move_slots_status()` for `RUVIO MOVESLOTS`, which moves a slot range to another shard of the same server, sync and asyncio.
- `hmset(key, mapping)` sends `HMSET` (multi-field `HSET` that replies `OK`; Redis marks it deprecated) (issue #26).
- Docs: `socket_timeout` is the command timeout; the README timeout table lists the matching option of every client (issue #48).
- Added `read_policy=` (`ReadPolicy.PRIMARY`, `PREFER_REPLICA`, `REPLICA`, or the strings `"primary"`, `"prefer-replica"`, `"replica"`) to the sync and asyncio cluster clients: commands the server flags read-only and not blocking go to one replica of the key's shard, picked when the slot table loads; a pipeline goes to replicas only when every command in it reads. A replica that cannot be connected or answers `LOADING` is skipped until the next load. Reads may miss recent writes (replication is asynchronous). The default keeps today's routing.
- `replicaof(host, port)`, `replicaof_no_one(force=False)` and `role()` for `REPLICAOF` and `ROLE`, sync and asyncio.
- Added `seeds=` (`"host:port"` strings or `(host, port)` tuples) to the sync and asyncio clients, `ClusterRuvio` and `from_url`: tried in order instead of `host`/`port`. A dropped connection reconnects starting with the next seed; a cluster reloads its slot map from the other known nodes and then the seeds when no open socket answers.
- Added keyword-only `ttl=` (seconds as `int`/`float`, or `timedelta`) to `incr`, `decr`, `incrby`, `decrby`, `incrbyfloat`, `hincrby`, `zincrby`, `setbit`, `zadd`, `geoadd`, `xadd`, `json_set`, `json_set_obj` and `bf_insert`. The deadline is set only when the call creates the key; an existing key keeps its deadline. Whole seconds send `EX`, a sub-second part sends `PX`; zero or negative raises `ValueError`.
- Added `ExpireCondition` (`NX`, `XX`, `GT`, `LT`) and the optional `condition=` argument on `expire`, `pexpire`, `expireat` and `pexpireat`. A key without a deadline counts as infinite; a failed condition returns `False`.
- `zpopbyscore` and `zmovedue` send `ZPOPBYSCORE` and `ZMOVEDUE`: take the due members of a sorted set (score up to a bound), or move them to the tail of a list, in one call.
- New `transfer(source, destination, amount, max=None)` and `htransfer(key, from_field, to_field, amount, max=None)` for the server's `TRANSFER` and `HTRANSFER`: they return a `(a, b)` tuple after the move, or `None` when nothing moved.

- `limit_sliding`, `limit_tokens`, `limit_sliding_with_retry` and `limit_tokens_with_retry` for the `SLIDING` and `TOKENS` modes of `LIMIT`, and the `LimitOutcome` result (needs a server that has them).

## 0.1.2 - 2026-10-17

- Added `StreamTrim` (`MAXLEN` or `MINID`, `=` or `~`, threshold) for `xadd(trim=...)` and `xtrim(trim=...)`, the `InfoSection`, `ClientType` and `ChangeType` enums (with `change_types()`), `StreamId`, `ScoreBound` and `LexBound` constants, and `score_exclusive()`, `lex_inclusive()` and `lex_exclusive()` bound builders. Existing string arguments keep working.
- Added typed keyword constants (`GeoUnit`, `GeoOrder`, `InsertPosition`, `ListSide`, `BitOperation`, `BitUnit`, `Aggregate`, `KeyType`, `BitFieldOp`, `Overflow`, `signed`, `unsigned`). They are `str` enums, so existing string arguments keep working; the encoder sends each member's pre-encoded bytes.

## 0.1.1 - 2026-10-17

- Cluster routing is cheaper: the command name and first key are read with one match per frame, a pipeline is routed in one pass into reused per-node buffers, every node is written before any is read, and a pipeline for one node goes out unchanged. Cluster CPU per pipelined request fell 8-17%; see `docs/evidence/2026-10-16-client-cluster-routing.md`.
- Fixed: with the optional `hiredis` parser installed, commands that answer `OK` (`set`, `select`, `auth`, `client_setname` and others) returned `False` instead of `True` when replies were not decoded (`decode_responses=False` or the `binary` view), because hiredis returns the reply as `b"OK"`.
- **Behavior change:** the cluster client now follows up to 3 `-MOVED` redirects per command (was 1) before raising `MovedError`. A command's first `MOVED` to a known node updates only that slot; the whole slot map is re-read only when the named node is unknown or the same command gets a second `MOVED` (before, any second `MOVED` since the last reload re-read it). Transactions follow the same limit.
- **Behavior change:** a cluster pipeline (not a transaction) containing `MGET`, `MSET`, `DEL`, `EXISTS`, `UNLINK` or `TOUCH` with keys in several slots is no longer refused with `CrossSlotError`: the command is split per slot like the plain command, and its place in the reply list holds the merged reply. A transaction must still use one slot.
- The cluster client now takes each command's key positions from the server's command table instead of its own hand-written lists, and is tested against the server's key vectors. No server command was routed by the wrong keys before; commands the server does not have (`BRPOPLPUSH`, `BZMPOP`, `EVAL_RO`, `EVALSHA_RO`, `FCALL_RO`, `LCS`, `ZINTERCARD`, `ZMPOP`, `ZRANGESTORE`, `LASTSAVE`, `QUIT`, `RESET`, `TIME`) now go by argument 1 like any other unknown command.
