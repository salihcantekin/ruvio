# Changelog

Notable changes to the Java client `io.github.salihcantekin:ruvio-client`. New entries go under "Unreleased"; `scripts/release_version.py` moves them under the version number when the package is released.

## Unreleased

- Fixed: following a failover after a `READONLY` reply skipped the node that refused in every round of the search, so a replica promoted a moment later (the usual case after the primary dies: the reconnect lands on the replica during the election) was used only once all rounds had run out, about 7 s with the default backoff. The refusing node is now skipped only while it still says `master` (a replaced primary does); once it answers `ROLE` as a replica, a later round takes it when it says `master`. Nothing changes while the connection is healthy.
- `RuvioOptions.Builder.followPrimary(boolean)` (default `true`) and `sentinelMaster(String)`: a standalone client with several seeds, or a coordinator name, finds the primary again after a failover. A reconnect runs one round of `ROLE` probes and connects to the node that answers `master` (a replica's reported primary is followed); a command answered `READONLY` runs up to 8 rounds (100 ms doubling to 2 s, off the reader thread), moves the connection to the primary and is sent once more (a second refusal is the result; pipelines and transactions are not sent again). With a coordinator name the first connect and every round ask `SENTINEL get-master-addr-by-name`. Nothing is sent while the connection is healthy; `followPrimary(false)` restores the old behavior.
- `clientDurability(replicas[, timeoutMillis])` sends `CLIENT DURABILITY REPLICAS n [TIMEOUT ms]`, and the option `durability(replicas[, timeoutMillis])` sends it on every (re)connect, so the server holds replies until that many replicas have the writes on disk.
- A cluster client now follows `-ASK slot host:port` (sends `ASKING` and the command to the named node in one write, discards the `+OK`, and leaves the slot map as it is) and retries `-TRYAGAIN` up to 3 times after waits of 5, 10 and 20 ms (scheduled, never slept on a reader thread), routed again by the current slot map. `ASK` and `MOVED` share the 3-redirect budget; the 4th redirect error, or a `TRYAGAIN` after the 3rd retry, goes to the caller. Only error replies are checked, by prefix.
- **Behavior change:** `StreamEntry.fields()` now returns `List<KeyValue<K, V>>` in stored order instead of a `Map`, so a field name written twice is no longer collapsed to its last value. Applies to `xrange`, `xrevrange`, `xread`, `xreadgroup`, `xclaim` and `xautoclaim`.
- `commandTimeoutMillis` now also bounds the async API: a `CompletableFuture` from `client.async()` fails with `RuvioException` ("no reply within N ms") when the server does not answer in time, so `async().get(k).join()` no longer waits forever on a half-open connection. A blocking command gets its own wait on top and a wait of 0 has no deadline, as for the synchronous calls. The check is one daemon thread per connection that scans the queued requests; each command only stores a deadline (no timer, no extra allocation). A late reply is read and dropped, so the connection stays in use. Pub/Sub and transaction connections have no such check (issue #81).
- **Behavior change:** `commandTimeoutMillis` (synchronous calls) is now 30000 by default (was 0, no limit); `0` turns it off. A blocking command gets its own wait on top (`BLPOP k 5` may take 5 s plus the timeout; a wait of 0, or one the client cannot parse, has no deadline; a pipeline takes its largest wait), and a Pub/Sub or `MONITOR` connection never times out while it waits for messages (issue #48 follow-up).
- `moveSlots(first, last, shard)` and `moveSlotsStatus()` for `RUVIO MOVESLOTS`, which moves a slot range to another shard of the same server, async and blocking.
- `hmset(key, fields)` sends `HMSET` (multi-field `HSET` that replies `OK`; Redis marks it deprecated) (issue #26).
- Docs: `commandTimeoutMillis` is the command timeout; the README timeout table lists the matching option of every client (issue #48).
- `RuvioOptions.Builder.readPolicy(ReadPolicy)` with `ReadPolicy.PRIMARY` (default), `PREFER_REPLICA` and `REPLICA`: a cluster client sends reads (commands the server flags readonly, not blocking) to one replica per shard, listed after the primary in `CLUSTER SLOTS` and picked when the slot map loads. A pipeline goes to replicas only when every command reads. A replica that cannot be opened or answers `LOADING` is skipped until the next load. Replication is asynchronous, so reads may miss recent writes.
- `replicaOf(host, port)`, `replicaOfNoOne(force)` and `role()` for `REPLICAOF` and `ROLE`, async and blocking.
- `RuvioOptions.Builder.seeds(...)`: `host:port` seed addresses tried in order instead of host and port. A dropped connection reconnects starting with the next seed; a cluster reloads its slot map from the other known nodes and then the seeds when no open socket answers.
- TTL on create: `Duration` overloads `incr`, `decr`, `incrby`, `decrby`, `incrbyMax`, `incrbyfloat`, `hincrby`, `zincrby`, `setbit` and `geoadd(key, nx, xx, ch, ttl, members)`, `jsonSet`/`jsonSetNx`/`jsonSetXx(key, path, json, ttl)`, and `ttl(Duration)` on `ZAddArgs`, `XAddArgs` and `BfInsertArgs`. The deadline is set only when the call creates the key; whole seconds are sent as `EX`, anything finer as `PX`.
- `expire`, `pexpire`, `expireat` and `pexpireat` overloads take an `ExpireCondition` (`NX`, `XX`, `GT`, `LT`); `ExpireCondition` now also has `fragment()`, like the other keyword enums.
- `zpopbyscore` and `zmovedue` (async and blocking) send `ZPOPBYSCORE` and `ZMOVEDUE`: take the due members of a sorted set (score up to a bound), or move them to the tail of a list, in one call.
- New `transfer(source, destination, amount[, max])` and `htransfer(key, from, to, amount[, max])` for the server's `TRANSFER` and `HTRANSFER`: they return the two balances after the move, or `null` when nothing moved.

- `limitSliding`, `limitTokens`, `limitSlidingWithRetry` and `limitTokensWithRetry` for the `SLIDING` and `TOKENS` modes of `LIMIT`, and the `LimitOutcome` record (needs a server that has them).

## 0.1.2 - 2026-10-17

- Typed keyword constants: new enums `InsertPosition` (`linsert`), `BitUnit` (`bitcount`), `GeoOrder` (`GeoSearchArgs.order`) and `KeyType` (`ScanArgs.type`), and `BitFieldArgs.Type.signed(n)` / `unsigned(n)` for BITFIELD types. The existing boolean and string overloads still work. Every enum, including `GeoUnit`, `ListDirection`, `BitOp`, `Overflow` and `Aggregate`, writes a pre-encoded constant, so the keyword costs no per-call encoding.
- More typed constants: `StreamTrim` (strategy `MAXLEN`/`MINID`, mode `=`/`~`) for `XAddArgs.trim` and the new `xtrim(key, StreamTrim)`, `InfoSection` for `info(InfoSection)`, `ClientType` for `clientList(ClientType)`, plus the id and bound helpers `StreamIds` and `RangeBounds`. The Java client has no `CHANGES SUBSCRIBE` call, so there is no change-type set. The existing overloads still work.

## 0.1.1 - 2026-10-17

- Cluster commands no longer copy their encoded frame for a possible `MOVED` retry, and a cluster pipeline finds its node groups by index and reuses them between flushes. Pipeline allocation per request fell by half to three quarters; see `docs/evidence/2026-10-16-client-cluster-routing.md`.
- Behaviour change: a cluster command now follows up to 3 `MOVED` redirects instead of 1 (the 4th is returned as the error). A `MOVED` points only that slot at the named node; the whole slot table is re-read with `CLUSTER SLOTS` only when that node is unknown or from the second `MOVED` for the same command on, and the retry always goes to the node the `MOVED` named (before, any second `MOVED` from any command triggered a reload).
- The cluster client now takes each command's key positions from the server's command table (`CommandKeyRules`, generated from `clients/testdata/commands.json`) instead of a hand-kept list, and a test checks them against the server's key vectors. Every vector already matched, so no command was routed wrong before; words the server does not know (such as `BRPOPLPUSH`, `LCS`, `ZRANGESTORE`, `ZMPOP`) now take the unknown-command default, the first argument.
